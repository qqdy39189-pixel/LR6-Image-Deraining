# 2. 实现一个简单的模型

## 1. 将实现好的模型代码放到 markdown 文件中

```python
import torch
import torch.nn as nn


class BaselineNet(nn.Module):
    def __init__(self):
        super(BaselineNet, self).__init__()

        # 第 1 层：输入有雨图像，RGB 3 通道 -> 64 通道
        self.conv1 = nn.Conv2d(3, 64, kernel_size=3, padding=1)
        self.relu = nn.ReLU(inplace=True)

        # 第 2～7 层：6 个 64 通道卷积层
        self.res_blocks = nn.ModuleList([
            nn.Sequential(
                nn.Conv2d(64, 64, kernel_size=3, padding=1),
                nn.ReLU(inplace=True)
            )
            for _ in range(6)
        ])

        # 第 8 层：预测雨层，64 通道 -> RGB 3 通道
        self.conv_out = nn.Conv2d(64, 3, kernel_size=3, padding=1)

    def forward(self, x):
        # 保存输入的有雨图像
        rainy_image = x

        # 提取初始特征
        features = self.relu(self.conv1(x))

        # 使用残差连接提取深层特征
        for block in self.res_blocks:
            residual = features
            features = block(features)
            features = features + residual

        # 预测雨层
        rain_layer = self.conv_out(features)

        # 原图减去预测雨层，得到去雨结果
        clean_image = rainy_image - rain_layer

        return clean_image
```

## 2. 图像去雨中扩大感受野的解决思路

### 一、问题分析

由原题分析，去雨网络需要在**不明显降低图像分辨率**的情况下，让特征既能关注局部雨丝，也能利用更大范围的图像信息。

### 二、我的解决方案

#### 1. 使用残差连接

残差网络在卷积块之间加入跳跃连接，将输入特征直接加到卷积变换后的特征上：

$$
y = F(x) + x
$$

其中，`x` 是输入特征，`F(x)` 是卷积层学习到的残差特征，`y` 是输出特征。

**优点：**

- 为梯度提供更直接的传播路径，缓解深层网络梯度消失、训练困难的问题。
- 让网络在保留原有信息的同时学习需要补充或修正的特征。
- 可以堆叠多个残差块，逐步扩大感受野。

#### 2. 使用空洞卷积

卷积时在卷积核元素之间留出间隔。

**优点：**

- 不需要池化，也可以扩大感受野。
- 特征图的宽度和高度可以保持不变（配合合适的 padding）。
- 计算量通常比直接使用更大的卷积核低。

**局限：** 如果空洞率设置不合理，可能产生采样不连续、遗漏局部细节等问题，所以可以组合使用不同的空洞率。

#### 3. 使用多尺度特征融合

可以设计多个分支，分别提取不同范围的信息：一个分支使用普通 `3×3` 卷积关注细小雨丝和纹理，另一些分支使用空洞卷积或更大的卷积核关注更大区域，之后再将各分支的学到的特征融合。

**优点：**

- 同时利用局部细节和较大范围的上下文信息。
- 对不同粗细、不同方向和不同长度的雨丝更灵活。
- 可以在不降低最终输出分辨率的情况下融合多尺度信息。

**局限：** 分支越多，模型结构和计算开销也越大，需要通过实验选择合适的分支数量。

#### 4. 使用注意力机制或非局部特征交互

普通卷积主要聚合附近像素的信息。注意力机制可以根据特征之间的相关性，让一个位置利用距离较远位置的信息。

**优点：**

- 有机会捕捉较远的结构关系，例如较长雨线在图像不同区域中的方向和连续性。
- 能根据图像内容动态决定哪些位置的信息更重要。

**局限：** 全局注意力在高分辨率图像上可能带来较高的显存和计算开销。实际使用时可以用窗口注意力、分块处理或轻量化注意力。

#### 5. 在网络中加入下采样与上采样的多尺度路径

采用类似 U-Net 的结构：编码阶段逐步缩小特征图以获取更大范围的信息，解码阶段再恢复分辨率，并通过跳跃连接补回浅层细节。

**优点：**

- 低分辨率特征能以较低成本覆盖更大的图像区域。
- 跳跃连接有助于保留边缘和纹理。
- 最终仍可输出与输入同尺寸的去雨图像。

**局限：** 下采样可能损失细节，所以下采样倍率不能太大。

### 三、总结我认为比较合适的方案

对于当前的图像去雨任务，我认为可以优先考虑**残差连接 + 空洞卷积 + 多尺度特征融合**的组合。

具体方法：

1. 先使用普通 `3×3` 卷积提取浅层特征，保留雨丝边缘和图像纹理。
2. 在中间网络中加入残差块，让网络更容易训练。
3. 在**部分**残差块中使用不同空洞率的卷积，使网络在保持特征图尺寸的同时获得不同范围的信息。
4. 将不同分支的特征融合，再通过输出卷积预测雨层。
5. 用输入的有雨图像减去预测雨层，得到去雨结果：

这样既可以利用附近区域的信息识别细小雨丝，也可以通过较大感受野利用更远处的上下文信息，同时借助残差连接降低深层网络的训练难度。

## 2. 学到的与代码相关的新东西

### 1. 两种导入方式的区别

- `import X`：导入整个模块，使用时要写 `X.成员`。
- `from X import Y`：只从模块 X 中导入指定的成员 Y，使用时可直接写 Y，不用带模块名前缀。

### 2. tqdm（进度条）

把它套在循环外面，运行时会在终端显示进度条、完成百分比，适合训练、批量处理等耗时任务。

### 3. argparse（命令行参数）

- 作用是让脚本接收并解析命令行参数。
- 参数不必写死在代码里，运行时从命令行传入即可，改参数不用改代码。

### 4. lpips（感知相似度）

- 提供 LPIPS 感知相似度指标。
- 原理不是逐像素比较，而是用预训练好的神经网络提取两张图的特征再比较差异，因此更符合人眼对"像不像"的判断。
- 数值越接近 0 表示两张图看起来越像，可在图像生成、风格迁移等任务中作损失函数，评价生成图与原图的相似程度。

### 5. argparse.ArgumentParser（参数解析器）

- 使用 argparse 前，要先调用 `argparse.ArgumentParser()` 创建一个参数解析器对象；之后先用它逐个声明要接收的参数，最后用 `parse_args()` 统一接收命令行实际传入的值。
- 创建时可以传入 `description` 参数，填写一段说明程序用途的文字；它会在运行脚本加 `-h` 时，显示在自动生成的帮助信息最上方。

### 6. parser.add_argument()：声明一个参数

- 基本格式：第一个是参数名，后面跟规则选项，不写的规则采用 argparse 的默认行为。
- `type`：指定传入值要转换的类型，注意命令行传入的值本质都是字符串，不指定 type 会按字符串处理。
- `default`：不传这个参数时自动使用的默认值。
- `required=True`：该参数必填，不传程序直接报错，此时 default 没有意义。
- `choices`：限定取值只能是给定列表中的一个，传入列表外的值会报错。
- `help`：该参数的说明文字，显示在 `-h` 帮助页中。
- `action="store_true"`：把参数变成开关型参数，不接收值；命令行中出现这个参数时值为 True，没出现时为 False。

### 7. tqdm 包裹可迭代对象、leave 参数

- tqdm 可以包裹任何可迭代对象。遍历包裹后的对象，取到的数据内容和先后顺序不变，但多了一条实时推进的进度条。
- `leave=True`：循环结束、进度条到达 100% 后，进度条保留在终端里。
- 把包裹后的对象存成变量，可以在循环过程中调用 `set_postfix()` 往进度条末尾动态添加要实时显示的信息。

### 8. 元组解包与 `_` 占位符

- 元组解包可以把一个元组里的多个元素一次性分别赋给多个变量，左边变量的个数必须和元组元素的个数一致。
- `_` 是占位变量名，表示"这个位置有值、但我用不到"，它可以占位来保证解包个数对齐。

### 9. register_buffer（PyTorch 缓冲区）

- PyTorch 的模型存放张量分三类：参数（Parameter）会被优化器更新；普通属性（直接 `self.x = 张量`）不随模型移动设备、也不会被保存进权重文件；Buffer 介于两者之间。
- 用 `register_buffer` 登记的张量不参与训练、不被优化器更新，但会随模型一起移动设备，也会被保存进 state_dict 权重文件。

### 10. nn.InstanceNorm2d（实例归一化）

- 对四维图像数据（N, C, H, W）的每一个通道，分别用该通道自身的均值和标准差做标准化。
- 构造时传入的参数是通道数，必须与上一层的输出通道数一致。
- 与 BatchNorm 的区别：BN 是对同一通道跨整批样本一起统计均值和方差，受 batch 大小影响，且要保存 running 统计量供测试时使用；IN 逐图逐通道统计，不受 batch 大小影响，也不需要 running 统计量，训练和测试时行为一致。
- 能抹平每张图自身的对比度等信息。

### 11. U-Net 的整体结构

- 编码-解码结构：下行（编码器）逐步缩小特征图尺寸、增加通道数，从看细节走向看语义；底部是瓶颈层，尺寸最小、通道最多；上行（解码器）再逐步放大尺寸、减少通道数，最终恢复到与输入相同的尺寸，整体呈 U 形。
- 跳连拼接：解码器每一层会把编码器中同尺寸那层的特征图沿通道拼接进来，把下行时丢失的细节补回来，通道数翻倍。它和残差连接不同，残差是逐元素相加（通道数不变）。

### 12. 转置卷积（ConvTranspose2d）

- 是普通卷积的逆操作，作用是上采样：把特征图尺寸放大。设置 kernel_size=2、stride=2 时，长宽翻倍。在解码器中用于恢复分辨率，同时可以调整通道数。

### 13. 1×1 卷积

- kernel_size=1 的卷积只在每个像素位置上对通道重新组合，实现通道数的升降。
- 用于网络出口，把特征的通道数调整为目标值。

### 14. U-Net 上行每层"转置卷积＋Block"成对备料

- 解码器的每一层由一对组成，顺序固定：先转置卷积、后 Block。转置卷积负责放大尺寸、减少通道，Block 负责加工特征，并把通道数压到该层的目标值。
- 两者的输入通道都按 feature×2 设计。转置卷积的 feature×2 是上一步产出的通道数，Block 的 feature×2 是"转置卷积的输出＋跳连拼接进来的编码器同层特征"合计后的通道数。

### 15. 转置卷积名称的由来

- 卷积运算在数学上等价于乘一个大矩阵，转置卷积相当于乘这个矩阵的转置，作用方向与普通卷积相反。
- 它只是尺寸上的逆操作，不是数值上的还原。下采样时丢失的细节无法凭空恢复，放大出的内容是靠训练学习出来的。

### 16. U-Net 跳连的拼接方式（torch.cat）

- 拼接发生在 forward 中，取用顺序与存档顺序相反（最深的那份最先用）。
- 拼接用 `torch.cat` 沿通道维（dim=1）进行：两份图的长宽不变、通道数相加。前提是两份特征图长宽一致。

### 17. 网络代码的分工：`__init__` 与 forward

- `__init__` 只负责定义"有哪些层、每层如何设计"，不处理数据。forward 才描述数据如何流动。
- `__init__` 里的参数是 forward 的线索：例如 Block 的入参写成 feature×2，正是因为 forward 中还会拼进来另一份 feature 。

### 18. torch.cat 的语法与拼接规则

- 语法：`torch.cat((张量1, 张量2, ...), dim=维度)`，第一个参数是装着待拼张量的元组（或列表），`dim` 指定沿哪一维拼接，不写默认 dim=0。
- 规则：参与拼接的张量维数必须相同，数据类型与所在设备也要一致。在拼接的那一维上，尺寸直接相加，在其他所有维度上，尺寸必须完全相等。

### 19. np.clip

- 把数组里的数值限制在指定的区间内。小于下限的改成下限，大于上限的改成上限，区间内的保持不变。
- 在这里是把模型输出的像素值夹回合法范围之后再做处理或评价。

### 20. clone()

- `clone()` 会复制出一个内容相同、但与原张量相互独立的新张量，这样在副本上做任何变换都不会改动原件。
- 既要加工一份数据，又要保留原始数据备用时，先 clone 再运算。

### 21. SSIM 的滑动窗口win_size

- `win_size` 是这个窗口的边长，必须取奇数（保证窗口有正中心像素）。窗口越大，比较越偏向全局；越小，越偏向局部细节。

### 22. load_state_dict

- 作用是把保存好的权重字典装回模型，按每层的名称逐一对应赋值。
- 因此模型的结构必须与存档时完全一致。

### 23. 优化器状态与断点续训

- 优化器自身也有状态需要保存和恢复，例如 Adam 为每个参数维护的动量缓存、学习率调度的进度。
- 断点续训要做到像没中断过一样继续，必须把模型权重和优化器状态成对存取。如果只恢复模型，优化器相当于冷启动，续训效果差。

### 24. next(iter(...))

- `iter()` 把可迭代对象（如 DataLoader）变成迭代器，`next()` 只从中取出第一个元素就停。
- 适合只需要一批样本的场合。

### 25. save_image 用 nrow 把一批图排成网格

- torchvision 的 `save_image` 能把一批图像张量自动排列成一张网格图，保存为单个图像文件。
- 参数 `nrow` 指定每行放几张图。把多组图先拼成一个大批次，再设好 nrow，就可以排出整齐的对照图。

### 26. 可迭代对象与迭代器（iter）

- 可迭代对象（如 DataLoader、列表）只负责存放数据，本身没有"取到哪了"的状态。`iter()` 把它变成迭代器，迭代器带有进度，记着当前取到哪一格。
- 每调用一次 `iter()`，都是一轮从头开始的新取用。

### 27. for 循环的底层机制

- for 循环本质上是先 `iter()` 得到迭代器，再反复 `next()` 取出下一个元素，元素取完时 `next()` 会抛出 StopIteration 信号，循环收到这个信号就结束。

### 28. 文件列表要先排序来保证配对

- `os.listdir()` 列出的文件名顺序由操作系统决定，不稳定。
- 当两个文件夹要靠文件名一一对应来配对时，必须先对文件列表 `sorted()` 排序，保证两边顺序一致。
- `sorted()` 把对象排序后返回一个**新列表**，不改变原对象。而 `list.sort()` 是原地修改原列表，没有返回值。

### 29. 数字字符串排序的坑

- 字符串排序是逐个字符比较大小。"1.jpg、2.jpg、……、10.jpg" 排完会变成 1、10、2 的顺序。
- 如果要依照人的理解排序，要给文件名数字补零（001.jpg、002.jpg），或排序时用 key 按数值提取。

### 30. 成对图像的随机变换必须同步

- 对成对数据（输入图与它的目标图）分别调用含随机操作的 transform 时，每次调用都会独立地重新随机一次，结果是这一对图的裁剪位置、翻转状态各不相同，图与答案发生错位。
- 这种错位不会报错、非常隐蔽，却会让模型拿着错位的图训练。正解是让一对图共用同一次随机结果，变换前设置同一个随机种子，或先抽好随机参数再分别应用到两张图上。

### 31. LPIPS(net=...)

- LPIPS 要借一个预训练网络当"眼睛"来提取图像特征再比较，`net` 参数就代表那张网，常用`alex`、`vgg`、`squeeze`。无论选哪个，骨干的权重都是冻结的，不参与训练。
- `alex`是最常用的，也是这个库的默认选择。第一，AlexNet 轻量、计算快，反复评分时开销小；第二，在 LPIPS 原论文的感知相似度评测中，AlexNet 提出的特征表现不比更深更大的 VGG 差、甚至更好。

### 32. num_workers 是 CPU 上的进程

- DataLoader 的 `num_workers` 指在 CPU 上并行加载数据的子进程数量。它们负责读文件、打开图片、做预处理变换，产出的是 CPU 张量。
- GPU 不参与数据加载，只负责模型的前向与反向计算。一批数据到了训练循环里，经 `.to(device)` 才被搬上 GPU 。
- 所以 num_workers 影响的是数据供给的速度（占用 CPU ），与显卡、显存无关。显存占用主要由 batch_size 决定。

### 33. map_location：让检查点按当前设备落地

- 检查点里的张量记着自己保存时所在的设备。默认加载时，`torch.load` 会把它们还原回原设备，原设备不存在时会报错。
- `torch.load(..., map_location=当前设备)` 强制把所有张量映射到指定设备上落地，使同一个检查点文件能在 CPU、GPU 之间通用。
