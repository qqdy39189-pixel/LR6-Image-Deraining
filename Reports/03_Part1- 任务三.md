# 2. 实现一个简单的模型

## 1. 将实现好的模型代码放到 markdown 文件中

```python
import torch
import torch.nn as nn


class BaselineNet(nn.Module):
    def __init__(self):
        super(BaselineNet, self).__init__()

        # 第 1 层：输入有雨图像，RGB 3 通道 -> 64 通道
        self.conv1 = nn.Conv2d(3, 64, kernel_size=3, padding=1)
        self.relu = nn.ReLU(inplace=True)

        # 第 2～7 层：6 个 64 通道卷积层
        self.res_blocks = nn.ModuleList([
            nn.Sequential(
                nn.Conv2d(64, 64, kernel_size=3, padding=1),
                nn.ReLU(inplace=True)
            )
            for _ in range(6)
        ])

        # 第 8 层：预测雨层，64 通道 -> RGB 3 通道
        self.conv_out = nn.Conv2d(64, 3, kernel_size=3, padding=1)

    def forward(self, x):
        # 保存输入的有雨图像
        rainy_image = x

        # 提取初始特征
        features = self.relu(self.conv1(x))

        # 使用残差连接提取深层特征
        for block in self.res_blocks:
            residual = features
            features = block(features)
            features = features + residual

        # 预测雨层
        rain_layer = self.conv_out(features)

        # 原图减去预测雨层，得到去雨结果
        clean_image = rainy_image - rain_layer

        return clean_image
```

## 2. 图像去雨中扩大感受野的解决思路

### 一、问题分析，提炼目标

由原题分析，去雨网络需要在**不明显降低图像分辨率**的情况下，让特征既能关注局部雨丝，也能利用更大范围的图像信息。

### 二、可能的解决方案

#### 1. 使用残差连接

残差网络在卷积块之间加入跳跃连接，将输入特征直接加到卷积变换后的特征上：

$$
y = F(x) + x
$$

其中，`x` 是输入特征，`F(x)` 是卷积层学习到的残差特征，`y` 是输出特征。

**优点：**

- 为梯度提供更直接的传播路径，缓解深层网络梯度消失、训练困难的问题。
- 让网络在保留原有信息的同时学习需要补充或修正的特征。
- 可以堆叠多个残差块，逐步扩大有效感受野。

**局限：** 残差连接本身不会让单个卷积核直接看到远处的信息；它主要是帮助训练更深的网络，从而间接扩大感受野。

#### 2. 使用空洞卷积

空洞卷积是在卷积核元素之间留出间隔。例如，`3×3` 卷积核的空洞率为 2 时，采样点覆盖的范围相当于 `5×5`，但参数量仍与普通 `3×3` 卷积相同。

**优点：**

- 不需要池化，也可以扩大感受野。
- 特征图的宽度和高度可以保持不变（配合合适的 padding）。
- 计算量通常比直接使用更大的卷积核低。

**局限：** 如果空洞率设置不合理，可能产生采样不连续、遗漏局部细节等问题。因此可以组合使用不同空洞率，而不是所有层都使用同一个较大的空洞率。

#### 3. 使用多尺度特征融合

可以设计多个分支，分别提取不同范围的信息：一个分支使用普通 `3×3` 卷积关注细小雨丝和纹理，另一些分支使用空洞卷积或更大的卷积核关注更大区域。之后再将各分支的特征融合。

**优点：**

- 同时利用局部细节和较大范围的上下文信息。
- 对不同粗细、不同方向和不同长度的雨丝更灵活。
- 可以在不降低最终输出分辨率的情况下融合多尺度信息。

**局限：** 分支越多，模型结构和计算开销通常也越大，需要通过实验选择合适的分支数量。

#### 4. 使用注意力机制或非局部特征交互

普通卷积主要聚合附近像素的信息。注意力机制可以根据特征之间的相关性，让一个位置利用距离较远的位置的信息。例如，窗口注意力可以在局部窗口内进行信息交互；非局部模块则可以直接计算不同位置之间的关联。

**优点：**

- 有机会捕捉长距离的结构关系，例如较长雨线在图像不同区域中的方向和连续性。
- 能根据图像内容动态决定哪些位置的信息更重要。

**局限：** 全局注意力在高分辨率图像上可能带来较高的显存和计算开销。实际使用时可以考虑窗口注意力、分块处理或轻量化注意力。

#### 5. 在网络中加入下采样与上采样的多尺度路径

虽然去雨任务通常希望输出保持原始分辨率，但这并不代表网络内部绝对不能下采样。可以采用类似 U-Net 的结构：编码阶段逐步缩小特征图以获取更大范围的信息，解码阶段再恢复分辨率，并通过跳跃连接补回浅层细节。

**优点：**

- 低分辨率特征能以较低成本覆盖更大的图像区域。
- 跳跃连接有助于保留边缘和纹理。
- 最终仍可输出与输入同尺寸的去雨图像。

**局限：** 下采样可能损失细节，所以下采样倍率不宜盲目增大，并应通过跳跃连接和重建损失帮助恢复细节。

### 三、方案比较

| 方法 | 如何帮助扩大信息范围 | 是否必须降低最终分辨率 | 主要注意点 |
| --- | --- | --- | --- |
| 残差连接 | 支持训练更深的网络，间接扩大感受野 | 否 | 本身不直接提供远距离信息 |
| 空洞卷积 | 增大卷积采样点之间的间隔 | 否 | 空洞率过大可能影响局部细节 |
| 多尺度特征融合 | 同时聚合不同范围的特征 | 否 | 结构和计算开销增加 |
| 注意力机制 | 让不同位置的特征直接或分组交互 | 否 | 全局注意力可能消耗较多显存 |
| 编码器—解码器 | 在低分辨率层获取更大范围的上下文，再恢复尺寸 | 否，最终可恢复原尺寸 | 下采样可能损失细节 |

### 四、总结我认为比较合适的方案

对于当前的图像去雨任务，我认为可以优先考虑**残差连接 + 空洞卷积 + 多尺度特征融合**的组合。

具体来说：

1. 先使用普通 `3×3` 卷积提取浅层特征，保留雨丝边缘和图像纹理。
2. 在中间网络中加入残差块，让网络更容易训练。
3. 在**部分**残差块中使用不同空洞率的卷积，例如空洞率为 1、2、3，使网络在保持特征图尺寸的同时获得不同范围的信息。
4. 将不同分支的特征融合，再通过输出卷积预测雨层。
5. 用输入的有雨图像减去预测雨层，得到去雨结果：

$$
I_{\text{clean}} = I_{\text{rainy}} - I_{\text{rain}}
$$

这样既可以利用附近区域的信息识别细小雨丝，也可以通过较大感受野利用更远处的上下文信息，同时借助残差连接降低深层网络的训练难度。

如果模型规模或显存有限，也可以先只加入空洞卷积或少量多尺度分支，再与原始模型比较，而不是一次加入所有复杂模块。

## 2. 学到的与代码相关的新东西

### 1. 两种导入方式的区别

- `import X`：导入整个模块，使用时要写 `X.成员`。
- `from X import Y`：只从模块 X 中导入指定的成员 Y，使用时可直接写 Y，不用带模块名前缀。

### 2. tqdm（进度条）

把它套在循环外面，运行时会在终端显示进度条、完成百分比和预计剩余时间，适合训练、批量处理等耗时任务。

### 3. argparse（命令行参数）

- Python 标准库，无需安装，作用是让脚本接收并解析命令行参数。
- 参数（如图片尺寸、学习率）不必写死在代码里，运行时从命令行传入即可，改参数不用改代码。

### 4. lpips（感知相似度）

- 第三方库，需用 pip 安装，提供 LPIPS 感知相似度指标。
- 原理不是逐像素比较，而是用预训练好的神经网络提取两张图的特征再比较差异，因此更符合人眼对"像不像"的判断。
- 数值越接近 0 表示两张图看起来越像；常用于图像生成、风格迁移等任务中作损失函数或评价生成图与原图的相似程度。

### 5. argparse.ArgumentParser（参数解析器）

- 使用 argparse 前，要先调用 `argparse.ArgumentParser()` 创建一个参数解析器对象；之后先用它逐个声明要接收的参数，最后用 `parse_args()` 统一接收命令行实际传入的值。
- 创建时可以传入 `description` 参数，填写一段说明程序用途的文字；它不影响程序功能，只会在运行脚本加 `-h` 时，显示在自动生成的帮助信息最上方。

### 6. parser.add_argument()：声明一个参数

- 基本格式：第一个参数是参数名（如 `--data_dir`，运行时以 `--data_dir 值` 的形式传入），后面跟若干规则选项；不写的规则采用 argparse 的默认行为。
- `type`：指定传入值要转换的类型（str、int、float 等）；命令行传入的值本质都是字符串，不指定 type 就按字符串处理。
- `default`：不传这个参数时自动使用的默认值。
- `required=True`：该参数必填，不传程序直接报错退出；它与 default 互斥——必填时默认值没有意义。
- `choices`：限定取值只能是给定列表中的一个，传入列表外的值会报错。
- `help`：该参数的说明文字，显示在 `-h` 帮助页中，不影响功能。
- `action="store_true"`：把参数变成开关型参数，不接收值；命令行中出现这个参数时值为 True，没出现时为 False。

### 7. tqdm 包裹可迭代对象、leave 参数

- tqdm 可以包裹任何可迭代对象（如数据加载器 DataLoader）：遍历包裹后的对象，取到的数据内容和先后顺序不变，只是多了一条实时推进的进度条。
- `leave=True`：循环结束、进度条到达 100% 后，进度条保留在终端里不消失；`leave=False` 则在结束后自动清除。
- 把包裹后的对象存成变量，可以在循环过程中调用 `set_postfix()` 往进度条末尾动态添加要实时显示的信息（如当前的损失值）。

### 8. 元组解包与 `_` 占位符

- 元组解包：可以把一个元组里的多个元素一次性分别赋给多个变量，左边变量的个数必须和元组元素的个数一致，否则报错。
- `_` 是约定俗成的占位变量名，专门接"这个位置有值、但我用不到"的情况，用不上也得用它占位来保证解包个数对齐。同一个解包中可以出现多个 `_`，互不影响。

### 9. register_buffer（PyTorch 缓冲区）

- PyTorch 的模型存放张量分三类：参数（Parameter）会被优化器更新；普通属性（直接 `self.x = 张量`）不随模型移动设备、也不会被保存进权重文件；Buffer 介于两者之间。
- 用 `register_buffer` 登记的张量不参与训练、不被优化器更新，但会随模型一起移动设备（如 `.cuda()`、`.to()`），也会被保存进 state_dict 权重文件。
- 适合存放"不需要学习、但必须跟着模型走"的数据，如 BN 层的 running_mean、running_var、预先计算好的位置编码等。

### 10. 残差连接（残差块）

- 结构：特征进入一个块之前，先把原输入留存一份（residual）；块加工后，再把原输入逐元素加回去，输出 = F(x) + x，其中 F(x) 是块的加工结果。这条把原输入直接送到输出的通路叫跳连（shortcut）。
- 作用一：块只需学习在原输入基础上要改动的增量（即"残差"），不必重新生成全部特征；当一层学不到有用改动时，F(x) 可趋近于 0，输出约等于输入，所以网络堆得再深也不会越练越差，缓解了深层网络的退化问题。
- 作用二：反向传播时，梯度可以沿跳连直接回流，不必层层穿过块内的运算被反复削弱，缓解梯度消失，使很深的网络也能正常训练。

### 11. nn.InstanceNorm2d（实例归一化）

- 用于四维图像数据（N, C, H, W）：对每张图的每一个通道，分别用该通道自身的均值和标准差做标准化，样本之间互不影响。
- 构造时传入的参数是通道数，必须与上一层的输出通道数一致。
- 与 BatchNorm 的区别：BN 是对同一通道跨整批样本一起统计均值和方差，受 batch 大小影响，且要保存 running 统计量供测试时使用；IN 逐图逐通道统计，不受 batch 大小影响，也不需要 running 统计量，训练和测试时行为一致。
- 常用于风格迁移、图像生成与修复类任务：逐图标准化能抹平每张图自身的对比度等风格信息。

### 12. U-Net 的整体结构

- 编码-解码结构：下行（编码器）逐步缩小特征图尺寸、增加通道数，从看细节走向看语义；底部是瓶颈层，尺寸最小、通道最多；上行（解码器）再逐步放大尺寸、减少通道数，最终恢复到与输入相同的尺寸，整体呈 U 形。
- 跳连拼接：解码器每一层会把编码器中对应同尺寸那一层的特征图沿通道维度拼接进来，通道数因此翻倍，把下行时丢失的高清细节补回给上行。它与残差连接不同：残差是逐元素相加（通道数不变），拼接是并排叠放（通道数增加）。
- 适用于图进图出的任务，如图像修复、图像分割。

### 13. 转置卷积（ConvTranspose2d）

- 是普通卷积的逆操作，作用是上采样：把特征图尺寸放大。设置 kernel_size=2、stride=2 时，长宽翻倍，常用于解码器中恢复分辨率，同时可调整通道数。

### 14. 1×1 卷积

- kernel_size=1 的卷积不改变特征图的长宽，只在每个像素位置上对通道重新组合，实现通道数的升降，不混合相邻像素的信息。
- 常用于网络出口，把特征的通道数调整为目标值（如从特征通道压回 3 通道的图像）。

### 15. U-Net 上行每层"转置卷积＋Block"成对备料

- 解码器的每一层由一对层组成，顺序固定：先转置卷积、后 Block。转置卷积负责放大尺寸、减少通道；Block 负责加工特征，并把通道数压到该层的目标值。
- 两者的输入通道都按 feature×2 设计，但来历不同：转置卷积的 feature×2 是上一步产出的通道数；Block 的 feature×2 是"转置卷积的输出（feature 个通道）＋跳连拼接进来的编码器同层特征（feature 个通道）"合计后的通道数——Block 的入参必须按拼接之后的通道数来定。

### 16. 转置卷积名称的由来

- 卷积运算在数学上等价于乘一个大矩阵，转置卷积相当于乘这个矩阵的转置（行列互换），作用方向与普通卷积相反，故名"转置"。
- 它只是尺寸上的逆操作（把特征图放大），不是数值上的还原：下采样时丢失的细节无法靠它凭空恢复，放大出的内容是靠训练学习出来的。

### 17. U-Net 跳连的拼接方式（torch.cat）

- 拼接发生在 forward 中：下行时先把每层池化前的特征图存档，上行放大后取出对应同层的存档来拼接；取用顺序与存档顺序相反（最深的那份最先用）。
- 拼接用 `torch.cat` 沿通道维（dim=1）进行：两份图的长宽不变、通道数相加。前提是两份特征图长宽一致，所以必须取下采样次数相对应的同层存档。

### 18. 读网络代码的分工：`__init__` 与 forward

- `__init__` 只负责定义"有哪些层、每层的尺寸如何设计"，不处理任何数据；forward 才描述数据如何流动（如在哪里拼接、在哪里相加）。
- `__init__` 里的尺寸参数是 forward 数据流的线索：例如 Block 的入参写成 feature×2，正是因为 forward 中还会拼进来另一份 feature 通道的特征。

### 19. torch.cat 的语法与拼接规则

- 语法：`torch.cat((张量1, 张量2, ...), dim=维度)`，第一个参数是装着待拼张量的元组（或列表），`dim` 指定沿哪一维拼接，不写默认 dim=0。
- 规则：参与拼接的张量维数必须相同，数据类型与所在设备也要一致；在拼接的那一维上，尺寸直接相加；在其他所有维度上，尺寸必须完全相等，否则报错。

### 20. np.clip（数值截断）

- 把数组里的数值限制在指定的区间内：小于下限的改成下限，大于上限的改成上限，区间内的保持不变。
- 常用于把模型输出的像素值夹回合法范围（如 [0, 1]）之后再做处理或评价。

### 21. clone()：先复制，再加工

- `clone()` 会复制出一个内容相同、但与原张量相互独立的新张量；在副本上做任何变换都不会改动原件。
- 当既要加工一份数据（如缩放数值范围）、又要保留原始数据备用时，先 clone 再运算。

### 22. SSIM 的滑动窗口打分（win_size）

- SSIM 不是把整张图一次性比较，而是用一个小窗口在图像上滑动，逐窗计算局部相似度，最后把所有窗口的得分平均为整张图的分数。
- `win_size` 是这个窗口的边长，必须取奇数（保证窗口有正中心像素）。窗口越大，比较越偏向全局；越小，越偏向局部细节。

### 23. load_state_dict：按名字装回权重

- 作用是把保存好的权重字典装回模型：按每层的名称逐一对应赋值。
- 因此模型的结构必须与存档时完全一致（名称、形状都对得上），否则会报错。

### 24. 优化器状态与断点续训

- 优化器自身也有状态需要保存和恢复，例如 Adam 为每个参数维护的动量缓存、学习率调度的进度。
- 断点续训要做到像没中断过一样继续，必须把模型权重和优化器状态成对地存、成对地取；只恢复模型会让优化器相当于冷启动，续训效果会打折。

### 25. next(iter(...))：只取一批数据

- `iter()` 把可迭代对象（如 DataLoader）变成迭代器，`next()` 只从中取出第一个元素就停，不必遍历全部。
- 适合只需要一批样本的场合，如保存示例图、快速预览。

### 26. save_image 用 nrow 把一批图排成网格

- torchvision 的 `save_image` 能把一批图像张量自动排列成一张网格图，保存为单个图像文件。
- 参数 `nrow` 指定每行放几张图；把多组图先沿批量维拼成一个大批次、再设好 nrow，即可排出整齐的对照图（如原图一行、生成图一行、标准图一行）。

### 27. 可迭代对象与迭代器（iter）

- 可迭代对象（如 DataLoader、列表）只负责存放数据，本身没有"取到哪了"的状态；`iter()` 把它变成迭代器，迭代器带有进度，记着当前取到哪一格。
- 每调用一次 `iter()`，都是一轮从头开始的新取用。

### 28. for 循环的底层机制

- for 循环本质上就是：先 `iter()` 得到迭代器，再反复 `next()` 取出下一个元素；元素取完时 `next()` 会抛出 StopIteration 信号，循环收到这个信号就结束。
- 手动组合 `iter()`＋`next()`，适合只需要取其中一两个元素的场景。

### 29. .to(device)：搬移张量到指定设备

- 参与同一次运算的张量必须位于同一台设备上（CPU 或某块 GPU），`.to(device)` 负责把张量搬过去；设备不一致会直接报错。
- `.to()` 不是原地修改，它返回搬好后的新张量，必须用赋值接住（如 `x = x.to(device)`），不接住就等于没搬。

### 30. 文件列表要先排序来保证配对

- `os.listdir()` 列出的文件名顺序由操作系统决定，并不稳定、不可靠。
- 当两个文件夹要靠文件名一一对应来配对（如输入图与目标图）时，必须先对文件列表 `sorted()` 排序，保证两边顺序一致，否则会出现图与答案张冠李戴的错位。
- `sorted()` 把对象按从小到大排序后返回一个**新列表**，不改变原对象。与它易混的 `list.sort()` 是原地修改原列表、没有返回值。

### 31. self.属性 = 参数：把配置登记到对象上

- 函数的参数是临时变量，函数一执行完就消失；写成 `self.x = x` 把它赋给对象的属性，值就存到了对象身上，只要对象活着，其他方法随时能通过 `self.x` 取用。
- 这是 `__init__` 的固定职责之一：把构造时传入的配置（路径、模式开关等）登记下来，供后续方法使用。

### 32. 数字字符串排序的坑

- 字符串排序是逐个字符比较大小，而不是按数字的数值大小："1.jpg、2.jpg、……、10.jpg" 排完会变成 1、10、2 的顺序。
- 应对办法：给文件名数字补零（如 001.jpg、002.jpg），或排序时用 key 按数值提取。

### 33. 成对图像的随机变换必须同步

- 对成对数据（输入图与它的目标图）分别调用含随机操作的 transform（随机裁剪、随机翻转等）时，每次调用都会独立地重新随机一次，结果是这一对图的裁剪位置、翻转状态各不相同，图与答案发生错位。
- 这种错位不会报错、非常隐蔽，却会让模型拿着错位的教材训练。正解是让一对图共用同一次随机结果，例如变换前设置同一个随机种子，或先抽好随机参数再分别应用到两张图上。

### 34. 像素损失与感知损失为什么要搭配使用

- 像素损失是逐像素对账：精确、稳定，保证输出在数值上与目标图一致（保真）。但它不懂观感，遇到拿不准的纹理会促使模型输出平均值，结果发糊、纹理被抹平。
- 感知损失比较的是预训练网络提取的深层特征（纹理、边缘、结构），贴近人眼判断，能让结果锐利、真实（保质感）。但它只管"像不像"，单独使用可能编造纹理、颜色漂移，数值上并不准。
- 两者加权搭配、互补短板：像素损失权重占大头，负责"对得上"；感知损失权重较小，负责把质感立起来。

### 35. LPIPS(net=...)：给评委选骨干网络

- LPIPS 要借一个预训练网络当"眼睛"来提取图像特征再比较，`net` 参数就是选哪张网：常用 'alex'（AlexNet）、'vgg'（VGG）、'squeeze'（SqueezeNet）。无论选哪个，骨干的权重都是冻结的，不参与训练。
- 'alex' 是最常用、也是这个库的默认选择，原因有二：第一，AlexNet 轻量、计算快，反复评分时开销小；第二，在 LPIPS 原论文的感知相似度评测中，AlexNet 提出的特征表现不比更深更大的 VGG 差、甚至更好——"判断两张图看起来像不像"这类任务，并不是网络越深越准的。

### 36. num_workers 是 CPU 上的进程，与 GPU 无关

- DataLoader 的 `num_workers` 指在 CPU 上并行加载数据的子进程数量：它们负责读文件、打开图片、做预处理变换，产出的是 CPU 张量。
- GPU 不参与数据加载，只负责模型的前向与反向计算；一批数据是到了训练循环里、经 `.to(device)` 才被搬上 GPU 的。
- 所以 num_workers 影响的是数据供给的速度（占用的是 CPU 和内存），与显卡、显存无关；显存占用主要由 batch_size 决定。

### 37. map_location：让检查点按当前设备落地

- 检查点里的张量记着自己保存时所在的设备（如某块 GPU）。默认加载时，`torch.load` 会把它们还原回原设备；原设备不存在时（例如在没有 GPU 的机器上打开 GPU 环境存的检查点）会直接报错。
- `torch.load(..., map_location=当前设备)` 强制把所有张量映射到指定设备上落地，使同一个检查点文件能在 CPU、GPU 及不同机器之间通用。
