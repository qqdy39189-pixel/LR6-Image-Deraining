# 1. 开头那句话有道理吗？对比学习一般具有哪些特征？

## 先给结论：有道理，但要说得更准一点

“这个感知损失变体，感觉和标准的对比学习不太一样吧？”——**有道理，而且不是感觉上的差别，是定义上的差别。**

更准确的说法是：它**借了对比学习的思想（拉近正样本、推远负样本），但不是标准对比学习的形式**。

## 狭义的“标准对比学习”长什么样

以 SimCLR v1、MoCo v1 为原型，一般有下面这些特征：

### 1. 任务是实例判别、无标签表征预训练

每张无标签图像自成一类。目标不是直接输出一张图，而是学一个能区分不同实例、又对同一实例的不同看法保持不变的编码器，预训练完再拿去做下游任务。

### 2. 正样本对来自同一图像的两次随机增强

同一张图做两次随机裁剪、颜色失真、模糊等，得到两个视图，互为正样本。这是 SimCLR / MoCo 定型后的标准做法。

### 3. 有显式的、大量的负样本

除正样本外的其他样本都当负样本，来源有三条路线：

- batch 内负样本：SimCLR，一个 batch 里除正样本外的所有视图都是负样本，所以需要大 batch；
- 队列 / 记忆库负样本：MoCo v1，队列 65536 个历史 key，动量编码器 m = 0.999 保证历史 key 和当前 query 可比，负样本数和 batch size 解耦；
- 两者结合：SimCLR v2 以 batch 内为主，另加 64K 记忆缓冲作补充（约 +1%，不是取代大 batch）。

负样本不是“陪跑”，它是提供排斥力的关键：没有它，所有表征坍缩成同一个常向量也能让“拉近正样本”这一项看起来完成任务。

### 4. 损失是 InfoNCE / NT-Xent 类的 softmax 辨别形式

带温度 τ 的形式：分子拉近正样本对，分母推远全部负样本，相当于从一堆候选里把正样本挑出来。CPC 最早把这个损失命名为 InfoNCE 并给出互信息下界解释，SimCLR 把它命名为 NT-Xent。只拉近不推远，理论上存在常数解；用 Wang & Isola 的语言，就是既要 alignment（正样本对齐），又要 uniformity（负样本在超球面上均匀铺开）。

### 5. 训练对象是编码器本身

对比损失直接训练要被复用的表征编码器（以及只用于对比损失的投影头，下游用投影前的表征），而不是训练一个下游任务网络、把对比当成辅助正则项。

### 6. 要解决“负样本又多又一致”的工程问题

SimCLR 靠大 batch 换负样本数；MoCo 靠队列加动量编码器换一致性；MoCo v3 去掉队列、回到大 batch 内负样本。这些都是标准对比的配套工程，不是可有可无的细节。

## 和标准对比的六处差别（开头那句话的道理）

1. **目标不同**：标准对比是无标签表征预训练，学一个可迁移的编码器；任务变体是有监督图像复原的辅助损失，目标是直接让去雨输出变好，编码器（VGG）根本不学。
2. **正负样本的定义不同**：标准对比的正样本是同一无标签图像的两次增强，负样本是其他图像；任务变体的正样本是**成对的干净真值**（有监督），负样本是**同一场景的有雨输入**（内容几乎相同，只差雨）。这个负样本是“极难负样本”：它和正样本共享全部背景内容，只在雨纹上不同，推远它时也要小心不要把共享背景也推远——这是标准对比里“不同图像作负样本”不会遇到的问题。
3. **负样本的数量和来源不同**：标准对比靠大量负样本（大 batch、65536 队列、64K 记忆）提供排斥力；任务变体每样本只有 **1 个正样本 + 1 个负样本**，没有 batch 内负样本、没有队列、没有记忆库，排斥力只来自那一项 sim_neg。
4. **损失形式不同**：标准对比是 InfoNCE / NT-Xent 的 softmax 辨别；任务变体是两个余弦相似度的线性组合，没有分母、没有温度、没有归一化成概率。它借的是对比的**思想**（拉近正、推远负），不是对比的**标准形式**。
5. **特征处理不同**：标准对比通常在投影后的低维表征上算相似度；任务变体先把 VGG 特征图全局平均池化成 512 维向量再算余弦，**只比方向、不比大小，且丢掉了空间位置信息**。这和原版感知损失也不一样：原版感知损失是在特征图上逐位置算 L1，保留空间结构；变体把它压成了全局方向比较。
6. **坍缩问题不同**：标准对比 / 无负样本路线要花大力气防表征坍缩（负样本排斥、EMA、stop-gradient、centering、均分约束）；任务变体里 VGG 是冻结的，根本不存在“编码器坍缩成常数”的问题，真正起锚定作用的是课程主损失（MSE 等像素损失）和成对真值监督，对比项只是辅助。如果只用这个对比项、不用像素主损失，单靠“离干净图近、离雨图远”并不能唯一确定一张图。

## 广义自监督里，哪些已经不是“标准对比”了

- **无负样本路线**：BYOL（EMA 慢目标网络 + 只在线侧的预测头 + stop-gradient）、SimSiam（权值共享 + stop-gradient + 预测头，连动量编码器也被拿掉了）、DINO（EMA 教师 + centering + sharpening，用分布匹配的交叉熵代替 InfoNCE）。它们靠不对称结构、慢目标、分布约束代替负样本的排斥力。
- **聚类路线**：SwAV 不直接比较两张图的特征，而是同时做在线聚类，强制同一张图不同视图的聚类分配一致，用 Sinkhorn-Knopp 均分约束防止所有图分到同一个类。它保留了“同图一致、不同图区分”的对比思想，但没有显式成对负样本。
- **前身 / 平行路线**：CPC（上下文 vs 未来）、NPID（自身身份 + 记忆库 + NCE）、ISIF（增强对 + batch 内实时特征 + 两项 softmax）、CMC（多视角 + 互信息）。它们已有对比骨架，但正样本定义、损失命名、负样本来源还不是后来定型的标准形式。

所以判断一句话：**只要没有“大量显式负样本 + InfoNCE / NT-Xent + 训练编码器”这三件套，就不能叫狭义的标准对比学习**，哪怕它也用了“拉近 / 推远”这个词。

# 2. 用对比学习的方式解释一下感知损失变体，对于这个预训练模型来说，什么是正样本？什么是负样本？

## 先把任务变体的事实钉死

文件是 `easy_contrastive_loss.py` 里的 `EasyContrastiveLoss`：

- 预训练模型和中间层**与感知损失完全相同**：VGG19 的 `features[:35]`（索引 0~34，到最后一个卷积层为止），ImageNet 均值 [0.485, 0.456, 0.406]、标准差 [0.229, 0.224, 0.225] 归一化。
- VGG 参数全部 `requires_grad = False`，且固定 `eval()` 模式。
- 每张图先过 VGG 得特征图 (B, 512, H, W)，再经 `AdaptiveAvgPool2d((1,1))` 压成 (B, 512, 1, 1)，摊平成 (B, 512) 向量。**空间信息在这一步被平均掉了**，只剩每通道的全局平均。
- `forward(input_image, generated, ground_truth)`：三路走同一条流水线，各得一条向量；`sim_pos = cosine(vec_gen, vec_gt)`（想让它大），`sim_neg = cosine(vec_gen, vec_input)`（想让它小）；`loss = (1.0 − sim_pos) + sim_neg`，再对 batch 取 mean。

## 对照表：锚点、正样本、负样本到底是谁

| 对比学习概念 | 在任务变体里的对应物 | 为什么是它 |
| --- | --- | --- |
| **锚点（anchor）** | **去雨预测 generated（vec_gen）** | 两个相似度都以 vec_gen 为一方：sim_pos 是 vec_gen vs vec_gt，sim_neg 是 vec_gen vs vec_input。锚点就是“正在被拉 / 被推的那个输出”，梯度也是回流到生成它的去雨网络。 |
| **正样本（positive）** | **无雨目标 ground_truth（vec_gt）** | 同一场景的干净真值。目标是让预测在 VGG 特征方向上靠近它，sim_pos → 1 时 (1 − sim_pos) → 0。 |
| **负样本（negative）** | **有雨输入 input_image（vec_input）** | 同一场景的退化版本。目标是让预测在特征方向上远离它，sim_neg 越小越好。 |
| **“编码器”** | **冻结的 VGG19 前 35 层 + 全局平均池化** | 它不是被训练的表征编码器，不更新、不动量、不排队；它只是一个固定的“裁判”，把三张图映射到同一个 512 维方向空间里再比方向。 |
| **真正被训练的网络** | **去雨网络本身（课程里的 UNet 等）** | 对比损失的梯度回流到生成 generated 的去雨网络，而不是回流到 VGG。这一点和标准对比完全相反：标准对比训练的是编码器，这里训练的是图像复原网络。 |
| **损失形式** | **(1 − sim_pos) + sim_neg 的直接相加，再 batch 平均** | 不是 InfoNCE / NT-Xent：没有 softmax 分母、没有温度 τ、没有“从一堆候选里挑出正样本”的分类形式、没有 batch 内其他样本作负样本、没有队列 / 记忆库。 |

## 为什么锚点是 generated，而不是有雨输入

这是最容易写反的地方，要单独强调：

如果把有雨输入当锚点，它在训练里是动不了的——有雨输入是给定的数据，不是网络的输出，梯度推不动它。

实际上两个相似度项的公共项都是 vec_gen，损失对 vec_gen 求导时，一项把它往 vec_gt 方向拉，另一项把它往 vec_input 的反方向推。所以**被移动的、被优化的只能是 generated**，它就是锚点；ground_truth 是它要靠近的正样本，有雨输入是它要远离的负样本。

## 对“对于这个预训练模型来说”这句话，要补一个限定

严格说，VGG 在这里**没有“自己的”正负样本要学习**，因为它根本不学习。它只是被三张图轮流“借用”来量方向：

- 送进 VGG 的三张图分别是：锚点图（去雨预测）、正样本图（干净真值）、负样本图（有雨输入）；
- VGG 对三张图一视同仁地做同一套变换：归一化 → 前 35 层 → 全局平均 → 512 维向量；
- 真正的“拉近 / 推远”发生在向量空间里比余弦相似度那一步，VGG 只负责把图变成向量，不负责决定谁该靠近谁。

所以说：

1. **按对比学习的角色分**：锚点 = 去雨预测，正样本 = 干净真值，负样本 = 有雨输入；
2. **按训练关系分**：VGG 是冻结的裁判，不是被训练的编码器；被训练的是去雨网络。

## 和原版感知损失的关系

原版感知损失根本没有正负样本的概念：它只是在 VGG 特征图上算 generated 和 ground_truth 的 L1 距离，越小越好，相当于只有“拉近”这一半。

任务变体是在这个基础上**加了一半对比思想**：保留“拉近预测和干净真值”，再加一项“推远预测和有雨输入”。所以它准确的名字应该是**感知损失的对比化变体**，而不是**标准对比学习在去雨上的直接应用**。
